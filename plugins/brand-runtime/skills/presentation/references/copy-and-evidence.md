# Copy and evidence

## Authority ledger

Track presentation content using three explicit states:

- **Source copy:** wording, numbers, and claims received from the user or source artifact.
- **Proposed copy:** an editorial alternative that has not been approved.
- **Approved copy:** wording explicitly accepted during the current project.

Never silently replace source or approved copy. When the user asks to compare versions, show source and proposal together before writing. Once a proposal is accepted, treat it as approved until the user reopens it.

## Editorial rules

- Lead with the decision, tension, or consequence instead of a generic topic label.
- Prefer one governing sentence per slide.
- Remove setup language that the visual already explains.
- Replace vague abstractions with the actual actor, behavior, system, or commercial implication.
- Keep terminology consistent across the deck. Explain necessary specialist terms once.
- Do not intensify a claim beyond its evidence.
- Do not translate literally when it damages clarity, but preserve factual meaning and approved terminology.
- Never use an em dash as an automatic stylistic separator. Use sentence structure, a colon, or a centered dot only when the chosen presentation system calls for it.

## Metrics and claims

For every quantitative statement, retain:

- value and unit;
- time window;
- denominator where relevant;
- source;
- whether it is observed, derived, estimated, proposed, or targeted;
- calculation or reconciliation note when definitions differ.

Do not turn a convenient difference into a named audience or opportunity without stating the derivation. When two systems use different stage definitions, show both readings and their common directional conclusion rather than claiming exact equivalence.

## Evidence hierarchy

Use this order:

1. Direct source data or supplied artifact.
2. Validated project analysis.
3. Explicitly marked inference.
4. Proposal or hypothesis.

Do not present levels 3 or 4 as observed fact.
